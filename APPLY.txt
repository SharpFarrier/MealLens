MealLens — APPLY
================

WHAT THIS IS
  A brand-new standalone Next.js 16 app (its own repo + Vercel project + URL). It shares ONLY the
  DispatchLens Supabase database (hjjovblqvzpcpijtrmer). No DispatchLens code is touched.

  Screens: Scan (counter), Report (counts + caterer reconciliation + CSV), People (add/remove +
  print ID cards), Settings (rates, concession rate, meal-window drum-wheel pickers).
  Auth: reuses DispatchLens Supabase accounts, gated on dispatch_user_access.can_canteen.

VALIDATED BEFORE SHIPPING
  - npm run test:logic  -> 21/21 pure meal-logic tests pass (windows, concession, extras)
  - npx tsc --noEmit    -> clean
  - npx next build      -> compiles, all 10 routes build

----------------------------------------------------------------------
STEP 1 — RUN THE MIGRATION IN SUPABASE *FIRST*
----------------------------------------------------------------------
  Open the Supabase SQL editor for project hjjovblqvzpcpijtrmer and run the file:
      supabase/migration.sql
  (also delivered separately in chat as meallens-migration.sql)

  It is safe/idempotent: adds can_canteen to dispatch_user_access and creates employees,
  canteen_items, canteen_scans, canteen_config with RLS + seed rows. It does NOT drop or
  rewrite any existing DispatchLens table.

  Then grant yourself access (replace the uid):
      update public.dispatch_user_access set can_canteen = true where user_id = '<your-auth-uid>';

----------------------------------------------------------------------
STEP 2 — UNZIP
----------------------------------------------------------------------
  Unzip into a new folder (the zip already contains a top-level meallens/ directory):
      unzip meallens.zip
      cd meallens

----------------------------------------------------------------------
STEP 3 — ENV
----------------------------------------------------------------------
  cp .env.local.example .env.local
  # then edit .env.local and set:
  #   NEXT_PUBLIC_SUPABASE_URL   = https://hjjovblqvzpcpijtrmer.supabase.co
  #   NEXT_PUBLIC_SUPABASE_ANON_KEY = <the anon key for that project>
  #   (optional) NEXT_PUBLIC_SUPERVISOR_PIN = <pin>   # defaults to 2468

----------------------------------------------------------------------
STEP 4 — INSTALL & RUN LOCALLY
----------------------------------------------------------------------
  npm install
  npm run dev
  # open http://localhost:3000  -> sign in with your DispatchLens account

----------------------------------------------------------------------
STEP 5 — CREATE THE REPO AND PUSH  (repo: SharpFarrier/MealLens)
----------------------------------------------------------------------
  Create an EMPTY repo on GitHub named MealLens (no README/gitignore), then:

      git init
      git add .
      git commit -m "MealLens: canteen meal counting + billing (shares DispatchLens Supabase)"
      git branch -M main
      git remote add origin https://github.com/SharpFarrier/MealLens.git
      git push -u origin main

----------------------------------------------------------------------
STEP 6 — DEPLOY (Vercel)
----------------------------------------------------------------------
  Import SharpFarrier/MealLens as a NEW Vercel project. Add the same env vars from .env.local
  in the Vercel project settings. Deploy. (Camera scanning needs HTTPS, which Vercel provides.)

NOTES
  - next-env.d.ts is gitignored and regenerated by `next dev` / `next build` (standard Next).
  - Per-person concession overrides already have columns (employees.lunch_rate/dinner_rate);
    billing uses the single config rate for now and can be switched to read them later.
